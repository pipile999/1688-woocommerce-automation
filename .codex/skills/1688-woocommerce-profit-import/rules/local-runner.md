# Standalone local execution

Repository entry: `python auto_import_runner.py <1688-url|products.xlsx|explicit-tasks.json>`. Excel selection: `--start X --end Y` uses the sequence column, not physical header rows. Default eligible new products Publish; `--draft` explicitly requests Draft. `--dry-run` blocks network, acquisition, credential initialization and all WooCommerce writes; offline payload IDs are synthetic.

Reuse `1688-cli/OpenCLI`, Python, actual local PaddleOCR/OpenCV/rembg/OpenCLIP where needed, exact SHA caches and perceptual image deduplication. No Codex runtime or LLM service is required for deterministic work. The Runner uses a literal controlled glossary for supported source types/options and source-hash-bound English evidence packs for prior reviewed translations. Unknown product types, ambiguous options, complex graphics, uncertain product identity, English meaning or SERP intent enter `ai-review-queue.json`; never silently guess or claim complete language coverage.

Keep per-offer atomic `checkpoint.json` and upload checkpoints under `output/auto-runner/`. Identity includes source facts, original URL, full raw image SHA inventory and current Skill/rules version. Exact unchanged stages and valid artifacts are reused; changed/missing artifacts invalidate reuse. Always re-read identifiers/prices and image dimensions; refresh live category, REST and HTTP publication gates. Preserve raw and prior results. No cross-offer cache reuse or semantic cache.

Use one fixed project browser session and persistent site profile, serial acquisition, immediate challenge pause. Do not close/reset the session. Open headed verification once, inspect browser state at conservative intervals, confirm whoami after the human solves it, and resume the same offer. Drain already-collected offers before requesting more 1688 data so local processing is not stranded behind verification. Record every trigger, offer, count, duration and resume outcome. Never rapidly repeat failed requests.

Initialize WooCommerce once and cache its category tree for the batch. Existing products outside this runner's own upload checkpoint are not automatically overwritten; an ambiguous/duplicate/source-inconsistent target stops only that offer. New uploads use an internal draft followed by all hard gates and Publish. Persist media/parent/variation write results immediately. An unknown POST outcome requires reconciliation, not a blind retry or duplicate creation. No critical FAIL can publish.

Record local_processing=true, actual keyword_api_queries, llm_calls, vision_calls, paid_api_cost and processing_time per offer. Distinguish local models from remote Vision calls. Zero external queries means zero external API spend; when an actual API cost cannot be measured, record null/DATA_UNAVAILABLE, not a guess. Normal supported products can use zero LLM/remote Vision calls; this is not a promise that unfamiliar semantics can be safely auto-approved.

Offline replay PASS means saved source/identifiers/prices/image lineage/geometry, cached keyword logic, category snapshot and payload construction passed. It does **not** mean current models, a real API credential, image HTTP or live publication were tested. Report those as NOT_EXECUTED. Real local inference is a separate `--process-images` mode and must report missing models/errors honestly. Do not infer a new-model PASS from legacy audits.
